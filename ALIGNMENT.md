# BirdWalk --- Alignment, Claims and Acceptance Contract

This document is the source of truth for product scope, contest
alignment, and truthfulness. If another instruction conflicts with this
file, follow this file and explain the conflict in
`IMPLEMENTATION_STATUS.md`.

## 1. Mission

Help people identify possible bird calls and spend more time observing
nature, not using a screen.

## 2. Challenge fit

The product must demonstrate: - An open-weight/open-source AI component
that is genuinely central to the working product. - An outdoor use
case. - A clear explanation of why local/open inference matters. - A
screen-minimizing experience, not an engagement-maximizing feed. - A
working demo and honest technical evidence.

## 3. Non-negotiable truth rules

Never invent: - Accuracy percentages - Confidence calibration - Field
testing or park visits - User interviews or testimonials - Offline
verification - Phone-native inference - Deployment status - Model
capabilities or species coverage - Sample licence or attribution

If a test has not happened, mark it `NOT TESTED`. If a result is only a
demo fixture, label it `DEMO FIXTURE`. If a result is generated by the
real model, label it `MODEL OUTPUT`.

## 4. Model score vs accuracy

-   **Model score:** the score returned by the inference model for a
    prediction.
-   **Top-1 agreement on a curated sample set:** the proportion of test
    samples where the top prediction matches the source label; this is
    not necessarily real-world accuracy.
-   **Top-3 agreement:** whether the source label appears in the first
    three predictions; also not a general accuracy guarantee.
-   **Field accuracy:** must not be claimed without a properly
    described, representative, independently verified field dataset and
    methodology.

For a small online sample set, use "smoke test" or "source-label
agreement" language. Do not present it as a robust accuracy benchmark.

## 5. Offline terminology

Allowed only after testing: - "Local inference on the backend machine"
if the model executes on that machine. - "Core inference tested without
network access" if the model and dependencies were already installed and
a disconnected test passed. - "Phone recording interface" if the phone
records audio but inference happens elsewhere.

Do not say "runs fully offline" if any required core step depends on the
internet. Do not say "runs on phone" unless model inference itself was
tested on the phone.

## 6. Licensing and attribution

Before selecting model weights or audio samples: 1. Inspect the exact
licence. 2. Check whether redistribution is allowed. 3. Check whether
the intended contest/demo use is compatible with licence conditions. 4.
Preserve required attribution. 5. Include source, creator, licence and
modifications for audio. 6. Do not remove or obscure BirdNET attribution
required by the selected distribution. 7. If uncertain, do not
redistribute the asset; provide an on-demand downloader only if the
source's terms permit it, or choose another asset.

The commonly referenced `tphakala/BirdNET-v2.4` model card declares CC
BY-NC-SA 4.0. That licence includes non-commercial and share-alike
conditions. Do not treat it as permission for unrestricted commercial
use.

## 7. Privacy

-   No third-party closed inference API.
-   No permanent raw audio storage by default.
-   No precise GPS collection in MVP.
-   No audio content in logs.
-   Temporary uploads must be cleaned up.
-   Explain the actual data flow in the UI.

## 8. Wildlife safety

Missions must not encourage feeding, touching, chasing, handling,
disturbing, or luring birds. Do not play recorded bird calls to attract
wildlife. Keep a respectful distance and follow local rules. Provide a
no-walking alternative where practical.

## 9. User experience alignment

The interface should: - Make recording and trying a sample easy. -
Explain permissions before asking. - Show useful uncertainty. - Avoid
excessive screen time. - Transition into a minimal "Phone away" mode. -
Be accessible, mobile responsive and visually distinctive. - Respect
reduced motion and readable contrast. - Never use fake progress or fake
results.

## 10. Definition of done

The MVP is complete only when: - React app builds. - FastAPI backend
runs. - Real pretrained model inference works. - At least one legally
usable sample goes through the complete pipeline. - Recording or upload
is connected to real inference. - Errors are handled honestly. - The
mission flow works without Gemma. - Attribution and licences are
documented. - A test report records actual commands and outcomes. - The
README makes no unsupported claims.

## 11. Optional Gemma category

Gemma is optional. It must not delay the core working app. Enter the
Gemma category only if: - A real Gemma model is actually integrated. -
It performs a meaningful user-facing task such as generating short
mission text. - The exact model and licence are documented. - A
deterministic fallback exists. - The demo proves the integration works.

Do not add Gemma just for a badge or category claim.

## 12. Conflict resolution

If visual polish conflicts with working inference, prioritize working
inference and honest proof, then polish the critical screens. If a model
dependency is incompatible or too heavy, report the issue and use a
documented supported route; never silently substitute random
predictions. If a feature cannot be completed, label it as future work.
